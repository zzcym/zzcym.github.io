2026.11.18 — 站点指南

这个博客是怎么写出来的

没有框架、没有构建、没有 CMS：一份关于这个角落里所有零件的说明书。

这是一份说明书，也是一次自我介绍。没有框架、没有构建、没有 CMS——只有几个 HTML 文件和一份 CSS。

为什么还要写博客

2026 年了，写博客这件事本身已经有点像行为艺术。所有内容都在往信息流里挤，每一句话都在等着被划走。但我还是想要一个地方：它不催我，也不需要讨好任何人。

一个自己的站点最奢侈的地方在于，它允许一个字待很久。你三个月不更新，它不会把你的权重降下来；你写一篇只有七十个人看得懂的技术笔记，它也不会给你限流。

一个网站最好的部分，往往是它没有被要求做的那些事。

整站只有七个零件

没有依赖，没有 node_modules，也不需要理解任何构建工具。整站由这几样东西拼起来：

零件文件作用
首页index.html一块会自己转的点阵球
列表writing.html全部文章，可以按标签筛
实验室lab.html可以抄走的小特效
文章posts/*.html每篇一个独立的 HTML
样式assets/css/style.css全站唯一一份 CSS
交互assets/js/core.js目录、快捷键、灯箱、搜索
索引posts.json脚本从每篇的 meta 读出来

一篇文章就是一个 HTML 文件

想写新的一篇，复制任何一个旧文件，改掉开头这四行字：

<meta name="post:title"   content="深色的手感">
        <meta name="post:date"    content="2026-10-24">
        <meta name="post:tags"    content="设计,界面">
        <meta name="post:excerpt" content="纯黑不是深色模式。">

然后跑一次 npm run build。脚本会把 posts/ 里所有文章重新读一遍，生成 posts.json 和 feed.xml。首页的“最近的写作”、列表页的标签筛选、⌘K 里的搜索结果，全都来自这一个文件。

i
如果你把仓库推到 GitHub，那个 Action 会在每次 push 时自动跑同一份脚本，所以这一步也可以忘掉。

想放动图？直接写 img

这是用 HTML 写东西最大的好处：没有 Markdown 的限制，想放什么就放什么。GIF、<video>、<canvas>、一段内联的 SVG 动画，都可以直接塞进正文。

<figure>
          <img src="/assets/img/loop.gif" alt="一个会动的图">
          <figcaption>动图、截图、SVG 都行</figcaption>
        </figure>

图会自动获得一圈发丝边框和一行说明文字，点一下会全屏放大。

那些让人“眼前一亮”的东西

外观之外，我还塞了几个小机关：

  • 任意页面按 ⌘ K（Windows 上是 Ctrl K）呼出命令面板，可以搜标题、标签，也可以直接跳页。
  • 鼠标划过页面时，会跟着亮一小块——像拿手电筒照。
  • 首页右侧那颗球可以点。它会炸开，然后慢慢收回去。
  • 文章右边有目录，往下滚的时候它会自己指着当前这一段。
  • 链接可以整段分享：右上角的按钮会把当前地址复制下来。

发布

git add .
        git commit -m "新文章：深色的手感"
        git push

GitHub Pages 会在一分钟内把改动推上线。没有部署脚本，没有 CI 的等待，也没有“构建失败”这种情绪。

就这些。如果你也想开一个，把整站拿走，改掉名字、邮箱和链接，就可以开始写了。

写点东西。

这个博客没有评论、没有统计、没有广告。只有一些被认真写下来的字，和一处可以随便逛逛的地方。
